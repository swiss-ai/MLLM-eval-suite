# Launchers

Shell entrypoints for running evaluations through a common interface. Framework-specific launchers live next to the top-level dispatcher.

- `eval.sh`: combined production dispatcher. Pass `--eval-framework lmms-eval`, `--eval-framework VLMEvalKit`, `--eval-framework Evaluator`, or `--eval-framework lm-evaluation-harness`; the dispatcher sets `ORCH_REPO_ROOT`, accepts common args such as `--model`, `--tasks`, `--suite`, `--mode`, `--submit-mode`, and `--run-id`, and calls the selected framework launcher. Use repeatable `--extra-framework-config <arg>` for framework-native argv tokens without `--` separators. The default `all` mode runs the two multimodal harnesses, `lmms-eval` and `VLMEvalKit`; text-only Evaluator and lm-evaluation-harness runs must be selected explicitly.
- `lmms-eval/eval.sh`: lmms-eval Apertus vLLM production submitter copied from the lmms-eval submodule and adapted to this repository layout. It submits `slurm/lmms-eval/eval_job.slurm`, reads suites from `task_suites/lmms-eval/`, and uses `cache/lmms-eval/`, shared runtime caches under `cache/`, `logs/lmms-eval/`, and `results/lmms-eval/`. Pass `--submit-mode interactive` to run the job script directly with `bash` on an already-allocated node instead of calling `sbatch`.
- `VLMEvalKit/eval.sh`: VLMEvalKit Apertus vLLM production submitter copied from the VLMEvalKit submodule and adapted to this repository layout. It submits `slurm/VLMEvalKit/eval_job.slurm`, reads suites from `task_suites/VLMEvalKit/`, and uses `cache/VLMEvalKit/`, shared runtime caches under `cache/`, `logs/VLMEvalKit/`, and `results/VLMEvalKit/`. Pass `--submit-mode interactive` to run the job script directly with `bash` on an already-allocated node instead of calling `sbatch`.
- `Evaluator/eval.sh`: NeMo Evaluator text benchmark submitter. It reads suites from `task_suites/Evaluator/`, launches one `slurm/Evaluator/eval_job.slurm` job per task in `--submit-mode batch`, or runs that same job script with `bash` in `--submit-mode interactive`. Evaluator tasks copy `configs/Evaluator/apertus_text_vllm_template.yaml` into `results/Evaluator/<RUN_ID>/<task>/config.template.yaml`, write resolved launcher values to `config.env`, and run with `nel eval run`.
- `lm-evaluation-harness/eval.sh`: direct EleutherAI lm-evaluation-harness submitter using `third_party/lm-evaluation-harness` via `PYTHONPATH`. It uses the HuggingFace backend and supports `--num-processes N` to run a task through `accelerate launch` across N local processes.

Each framework launcher creates one `RUN_ID` directory per invocation and passes that shared output/log root to all Slurm jobs from the call.

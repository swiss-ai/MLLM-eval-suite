# Slurm

Store reusable Slurm templates for framework-specific batch jobs and shared environment setup. Keep account, partition, image, and model paths configurable.

- `lmms-eval/eval_job.slurm`: lmms-eval Apertus vLLM production job template copied from the lmms-eval submodule and adapted to this repository layout. It uses `toml/lmms-eval/apertus-vllm-lmms-eval-prod.toml`, `cache/lmms-eval/` for image-token cache, shared runtime caches under `cache/`, and `results/lmms-eval/`.
- `VLMEvalKit/eval_job.slurm`: VLMEvalKit Apertus vLLM production job template copied from the VLMEvalKit submodule and adapted to this repository layout. It uses `toml/VLMEvalKit/apertus-vllm-vlmevalkit-prod.toml`, `cache/VLMEvalKit/` for framework cache, shared runtime caches under `cache/`, and `results/VLMEvalKit/`.
- `Evaluator/eval_job.slurm`: NeMo Evaluator single-task wrapper. The outer Evaluator launcher submits one job per task and this template reuses `toml/shared/apertus-vllm-vision-eval-prod.toml`; Evaluator then starts Apertus through managed local vLLM inside the job and writes under `results/Evaluator/<RUN_ID>/`.
- `lm-evaluation-harness/eval_job.slurm`: direct lm-evaluation-harness single-task wrapper. The outer launcher submits one job per task and this template reuses `toml/shared/apertus-vllm-vision-eval-prod.toml`, then dispatches the local lm-evaluation-harness runner from `third_party/lm-evaluation-harness` and writes under `results/lm-evaluation-harness/<RUN_ID>/`. It enables `parallelize=True` for HF model sharding, so use `--num-processes 1` for a checkpoint that needs all visible GPUs to fit.

# Eval Suite Audit — 2026-07-02

13-agent audit (6 subsystem mappers, 6 adversarial verifiers, 1 completeness critic) of the
MLLM-eval-suite: orchestration layer, both harness forks, benchmark coverage/dashboard
integrity, the geospatial PR, and the text-eval landscape.

## Verdict

**B-grade: strong breadth and genuinely good Apertus-specific code, but not yet a
reproducible, team-grade system.** Directionally reliable for one operator's ablation
tracking. Missing: verification wired into the refresh, git-pinned runtime code, and
several things only work on one account, on this cluster, before the reservation expiry.

## What's genuinely good

- ~80 unique image benchmarks (VQA, math/reasoning, OCR/doc/chart, 8+ spatial,
  hallucination, GUI grounding, medical), 12 Apertus checkpoints, 90% dashboard cell fill.
- lmms-eval fork: 60 well-scoped commits with tests; the Apertus wrapper is a minimal
  13-line subclass; the media-encoder rework removes a real stale-frame footgun.
- VLMEvalKit fork: 7 clean commits; register-by-path is a genuine architecture
  improvement; all 75 suite names resolve; merge into upstream is textually clean.
- Honest curation trail: contaminated cells and CharXiv dropped with documented reasons,
  centralized headline-metric policy, per-cell provenance, judge-fail-rate guard.

## Trust problems (verified, ranked)

1. **Two time bombs.** Reservation `SD-69241-apertus-1-5-0` hardcoded in both slurm
   templates ends 31 Jul 12:00; no launcher override flag. The gpt-4-turbo judge remap
   exists only as an uncommitted edit to VLMEvalKit `judge_util.py` — a fresh submodule
   checkout silently reverts MMVet judging to a retired OpenAI model.
2. **What executes isn't what git pins.** lmms-eval runs from container-baked
   `/workspace/lmms-eval` built from the moving branch (no SHA recorded); VLMEvalKit runs
   a dirty working tree. (lmms-eval submodule object store was also corrupt — repaired
   2026-07-02 via `git fetch --refetch`.)
3. **Verification unwired.** `verify_dashboard.py` has zero callers and only parses the
   lmms-eval side; all 19 VLMEvalKit rows regenerate unaudited. Cells picked by newest
   mtime, no run pinning. VK ingester takes the lexicographically last `*acc*.csv` without
   checking the dataset name (mis-placed CSVs already exist in the bridge).
4. **Judge scores silently degrade.** No OPENAI key plumbing in launchers/slurm/toml;
   2026-07-01 MMSafetyBench logs show "Judge model is not working, fallback to exact label
   parsing". Thinking-mode deliberation-strip fix stranded on
   `yxu/eval-scoring-thinking-fixes` while the launcher passes `enable_thinking=True`.
5. **Single-operator hardwiring.** Personal paths + `|| true` in
   `derive_vlmeval_acc.py`/`refresh_dashboard.sh`; READMEs reference four nonexistent
   files; zero CI/tests on the scripts computing published numbers; results/caches on
   purgeable personal scratch; repo is public with main 42 commits behind.
6. **Defined-but-never-run.** All 27 audio tasks: zero results. ScreenSpot/OSWorld_G/
   3DSRBench/VSI-Bench ran but never reach the dashboard (no acc.csv → silent skip).
   MMSafetyBench produced scores for 4/6 models, not ingested. `mmlu_medical` (8.1–63.0
   swing) kept despite `mmlu_flan` dropped for the same fragility. ~45/55 lmms visual
   tasks also run in VLMEvalKit (duplicated compute). Gaps: video, long-context,
   multilingual multimodal, external baselines.

OVERALL TAKE: This is a strong single-operator eval pipeline by internal-tooling standards — ~80 benchmarks with honest curation, fail-fast orchestration contracts, per-cell provenance, and two competently maintained harness forks — and the audit's per-area findings are accurate where I re-verified them (verify_dashboard unwired, judge hotfix uncommitted, reservation expiry). Net verdict: a B-grade suite — directionally reliable for one operator's ablation tracking, but not yet a reproducible, team-grade evaluation system, and any individual dashboard number should be treated as re-derivable only by the original operator on this cluster before 2026-07-31.
